# Package the native app

[Development setup](../../contributing/development.md) · [Release process](../../contributing/releasing.md) · [Platform limits](../../docs/platform-and-limits.md)

Build on the target host: macOS arm64 or Ubuntu 24.04 x64. Local packaging creates files; installation, upload, Developer ID signing, and notarization are separate actions.

## Prepare inputs

Use Node.js 24 or newer and the platform tools listed in development setup:

```sh
npm ci
npm run native:runtime
npm run native:git-runtime
npm run native:build
npm run native:test
```

`native-runtime.mjs` selects the host target. `runtime*.json` and `git-runtime*.json` pin Electron and Git; `search-runtime.mjs` pins search inputs. Preparation downloads verified archives and retains Git corresponding source, recipes, and licenses. Builds fail on missing or changed prepared inputs. Packaged Git and ripgrep have no system-Git or PATH fallback.

Set `ASMB_TEST_ROOT` to an absolute physical directory disjoint from the checkout. Standalone clones default to sibling `../asMagicBrain-Test`. Keep fixtures, profiles, scratch work, candidates, and evidence there; never qualify against personal data.

## Create packages

```sh
# Candidates permit source changes and use unique test output.
npm run native:package -- --candidate
npm run native:package -- --candidate --channel=preview

# Final packages require clean source and its exact immutable tag.
npm run native:package
npm run native:package -- --channel=preview
```

`release.json` owns version/build. Final packaging requires no tracked or untracked changes and an exact `native-v<version>` tag at HEAD. Authorized metadata reissues use `native-v<version>-metadata.<revision>`. See [version rules](../../contributing/releasing.md#version-and-source-identity).

Advance the public version once per release. Retained internal test builds advance `buildNumber` and use `--candidate`, which creates unique test output without consuming a public version or final tag. A candidate may keep the current base version; label it with its candidate status, build number, and actual source commit. Its package metadata and manifest use `sourceTag: null`; the manifest retains input hashes and the dirty-source flag. Published or distributed final artifacts and tags remain immutable; a candidate does not replace them.

On Linux, a candidate with the same base version has the same Debian package version, so its higher `buildNumber` does not advance package-manager upgrade ordering. Explicitly reinstall it in an isolated test environment. `--candidate` selects packaging behavior; use the development channel's isolated data or pair preview `--test-root` and `--test-user-home` for isolated application testing.

| Target/channel | Final output |
| --- | --- |
| macOS development | `releases/<version>/asMagicBrain.app` |
| macOS preview | `releases/<version>-preview/asMagicBrain.app` |
| Linux development | `releases/<version>-linux-x64-development/asmagicbrain_<version>_amd64.deb` |
| Linux preview | `releases/<version>-linux-x64-preview/asmagicbrain-preview_<version>_amd64.deb` |

Existing outputs are never replaced. Failed staging is retained. Each result includes a package manifest, checksums, and packaging evidence binding source, channel, runtime, dependencies, documentation, and public account configuration.

Both channels include standalone user docs, their manifest, LICENSE/NOTICE, dependency notices, and bundled Git corresponding source. Keep the complete bundle together. The host installs docs as a protected local repository and preserves older editions.

Development uses isolated test data and shows deferred controls. Preview uses implemented-only controls, `~/asMagicBrain`, and a separate OS profile. For isolated preview acceptance, pair `--test-root` with `--test-user-home` inside that root. Ownership checks reject foreign or ambiguous data. See [data locations](../../docs/data-and-recovery.md).

## Ubuntu 24.04 x64 packages

Linux output is a Debian `amd64` package compressed with Zstandard level 6 and at most four threads. The packager extracts the completed `.deb` and compares its entire payload: paths, hashes, modes, and internal links. Temporary payload/extraction trees go to external test evidence; failed copies retain originals and partial output.

| Channel | Installed executable |
| --- | --- |
| Preview | `/opt/asmagicbrain-preview/asmagicbrain` |
| Development | `/opt/asmagicbrain/asmagicbrain` |

Verify the reviewed package and install it through APT:

```sh
sha256sum --check SHA256SUMS
sudo apt install ./asmagicbrain-preview_VERSION_amd64.deb
```

APT resolves the dependencies generated by `linux-package-policy.mjs`:

```text
apparmor (>= 4.0), libc6 (>= 2.39), libasound2t64,
libatk-bridge2.0-0t64, libatk1.0-0t64, libatspi2.0-0t64,
libcairo2, libcups2t64, libdbus-1-3, libdrm2, libexpat1,
libgbm1, libglib2.0-0t64, libgtk-3-0t64, libnspr4, libnss3,
libpango-1.0-0, libx11-6, libxcb1, libxcomposite1, libxdamage1,
libxext6, libxfixes3, libxkbcommon0, libxrandr2, ca-certificates,
xdg-utils, util-linux, zlib1g, libcurl4t64, libudev1, libgcc-s1
```

Users need no Node.js, build tools, or separate Git. The app runs as the ordinary desktop user from the fixed root-owned path. Its AppArmor profile grants user namespaces to that executable and reloads on configuration/upgrade. Removal unloads the profile without deleting user data. Keep global restrictions and Chromium sandboxing enabled; there is no setuid helper and `--no-sandbox` is refused. Moving the executable loses that grant. Source launches need a reviewed exact-path policy.

Linux fuses allow RunAsNode for fixed workers and disable NODE_OPTIONS and Node CLI inspection. Cookie encryption stays off; accounts remain in session memory. The desktop launcher accepts no file/URL arguments and registers no MIME associations.

Preview data stays in `~/asMagicBrain/`; the profile uses `$XDG_CONFIG_HOME/asMagicBrain Preview` or `~/.config/asMagicBrain Preview`. Package upgrade/removal does not migrate or delete these folders.

Each launch needs a short Chromium socket directory: a private `asmb-*` directory under a validated user-owned `0700` XDG_RUNTIME_DIR, or physical root-owned sticky `/tmp` if unset. The path is at most 64 UTF-8 bytes. Normal quit verifies identity before removal; crashes leave it for OS cleanup. Durable workspaces, drafts, and recovery state remain in their normal locations.

See [Ubuntu installation](../../docs/getting-started.md#install-on-ubuntu) for user instructions. No package repository or auto-updater is configured; checksums provide integrity, not a signing identity.

## Accounts and signing

Accounts default to `offline`. Select `ASMB_ACCOUNT_CONFIG=official` or an absolute public-registration JSON file when building and packaging. Use the same selector for the qualified variant. No secrets are accepted, and runtime environment variables cannot replace packaged registration. See [account configuration](../../contributing/development.md#configure-optional-accounts).

For macOS Developer ID signing and notarization, follow [the signing guide](../../contributing/macos-signing.md). It includes exact command/configuration examples and preserves the original package. Signing credentials and Apple submission require authorization.

## Accept the exact artifact

Run [native acceptance](acceptance/README.md) against the unchanged final package. Check runtime inventories, signatures where applicable, local workflows, and normal close/restart. Linux also needs installation, sandbox, desktop, and upgrade/removal checks; record the desktop/session and emulated or physical hardware.

A local ad hoc Mac pass does not establish Developer ID, notarization, or independent Gatekeeper acceptance. Keep production entitlements and fuses intact. Preserve evidence and report skipped or simulated checks accurately. Follow [source export and publication](../../contributing/releasing.md#source-export) for those separate steps.
